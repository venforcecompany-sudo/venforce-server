# ─────────────────────── ESTRUTURA REAL ───────────────────────
#  A empresa NÃO é "Squad → Gestor → membros". É:
#
#     Squad → Coordenador
#           → Gestor
#           → Auxiliar
#           → Auxiliar 2 (quando houver)
#           → Design
#
#  COORDENADOR e GESTOR são pessoas e funções DISTINTAS. O tooling V1
#  tratava Gestor como `squad_members.funcao = "coordenador"`; isso estava
#  semanticamente errado e foi corrigido nesta fase.
#
# ─────────────────── MAPEAMENTO PARA O MODELO ───────────────────
#  DUAS DIMENSÕES SEPARADAS, e a separação é preservada de propósito:
#
#   SQUAD MEMBERSHIP (`squad_members.funcao`) = acesso/participação
#     Coordenador ......... funcao = coordenador
#     Gestor .............. funcao = membro
#     Auxiliar/Auxiliar 2 . funcao = membro
#     Design .............. funcao = membro
#
#   CLIENT RESPONSIBILITY (`cliente_responsaveis.papel`) = gestor|auxiliar|designer
#     POR CLIENTE — e NÃO por Squad. Como Cliente→Squad ainda não chegou,
#     NENHUM `cliente_responsaveis` é criado nesta fase. A função
#     organizacional de cada pessoa fica preservada AQUI, neste arquivo,
#     para virar `responsaveis[]` quando a carteira chegar.
#
#   NENHUM enum novo foi criado em `squad_members.funcao`. Ele continua
#   `('membro','coordenador')` — ver 05_ESTADO_SCHEMA_SQUADS.md.
#
# ───────────────────────── MARCADORES ─────────────────────────
#   PENDENTE_*                    → dado ainda não conhecido (bloqueia plano)
#   AUSENTE_NA_ESTRUTURA          → o cargo NÃO EXISTE neste Squad (não é falta)
#   PENDENTE_CONFIRMACAO          → não sabemos se está vazio ou fora do recorte
#   PENDENTE_RELACAO_CLIENTE_SQUAD→ carteira ainda não recebida
#
# ────────────────────────── VALIDAÇÃO ──────────────────────────
